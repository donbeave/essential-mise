## Open gates

Confirm release sources and contracts, inspect upstream default branches and existing PRs, establish behavior tests and safe lifecycle semantics, verify in a disposable guest, and record actual PRs and evidence. Individual guest behavior results and outstanding lifecycle gates are recorded below.

The earlier scripts had source-identity, collision and failure-isolation risks. The committed runner validates Claude and Codex marketplace state, preserves disabled Claude installations, uses Muse's same-source install, and attempts both plugin scripts even when one fails. Guest tests cover these boundaries. Both OMP and OpenCode routes now report `PENDING` and leave existing files untouched; their remaining blockers are recorded below.

OMP 18.16.0's shared marketplace cache has a verified cross-project update hazard. In a synthetic guest fixture, updating a user installation to a version already used by another project replaced that project's cached plugin content. The manager uses a version-keyed cache and lacks cross-process locking, so a pre-check cannot rule out a concurrent collision. Evidence: guest `/tmp/essential-mise-evidence/omp-cache-review/repro.sh`, SHA-256 `844459a5cda54baec8f8867d7ac451ede31e212a9c064e984c59fb89583a2092`; related upstream [issue #16827](https://github.com/can1357/oh-my-pi/issues/16827) and [PR #17924](https://github.com/can1357/oh-my-pi/pull/17924) do not establish a fix for this case. Preserve existing OMP installations and report their update as pending until a safe route is established.

Kimi's documented installation is through `/plugins` in the TUI; local installations are copied into a managed per-user location, updates require reinstalling, and removal leaves the managed copy. Its `sessionStart.skill` injects skill text and does not execute code. The current i-have-adhd manifest declares skills but no session-start activation. This is an observed manifest property, not a conclusion that its opt-in behavior is broken. pstack has no Kimi manifest in the inspected checkout. Any integration must account for Kimi's namespaced skills and its own activation semantics.

OpenCode's stable documentation describes JavaScript or TypeScript plugin functions loaded from plugin directories or configured npm packages. Standalone skills are a separate mechanism. The existing pstack checkout documents a standalone skills fallback, which does not satisfy this task's native-plugin requirement. The i-have-adhd checkout contains an OpenCode adapter; whether the essential-mise loader and adapter work together remains unverified.

In OpenCode 1.19.5, [skill discovery](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/skill/index.ts) can run without initializing the [plugin service](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/plugin/index.ts). The [debug skill command](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/cli/cmd/debug/skill.ts) is one such path. A plugin config hook that adds its bundled skill directory may therefore be too late for discovery. This finding must be rechecked on Homebrew stable 2.2.5 before relying on it. `.audit/opencode-discovery-repro.sh` is prepared for the disposable guest and includes a static-path positive control; it has not yet run. A replacement custom tool would not automatically provide native skill-picker and slash-command semantics.

OMP 18.16.0's [installer documentation](https://github.com/can1357/oh-my-pi/blob/v18.16.0/docs/plugin-manager-installer-plumbing.md) accepts `git:github.com/owner/repo` and its [extension documentation](https://github.com/can1357/oh-my-pi/blob/v18.16.0/docs/skills/authoring-extensions.md) accepts `pi.extensions` as a legacy package manifest. The inspected pstack package declares `pi.skills` and `pi.extensions`. This supports the installation route as a contract lead, but does not prove the Pi extension's events or skills work under OMP. Git plugin installs are user-scoped, upgrades re-resolve the recorded ref and preserve enablement, and installed plugins execute trusted code. Scope, collision, retry and activation behavior still need guest tests.

OMP's [installed-plugin discovery source](https://github.com/can1357/oh-my-pi/blob/v18.16.0/packages/coding-agent/src/discovery/omp-plugins.ts) scans a package-root `skills` directory, while pstack declares a nested `pi.skills` path.
